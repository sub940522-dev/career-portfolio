# (주)쇼박스 정산시스템 신규구축

- 기간: 2025.11 – 2026.05 (가오픈까지 참여)
- 소속/역할: A팀(CMS·정산시스템 개발) — 팀장 직속 개발자. 전체 개발 인원 약 12명, 3개 팀
  - A팀: CMS·정산시스템 / B팀: 외부 연동 / C팀: 퍼블리싱·더존(ERP) 연계
- 기술: Java, JavaScript, Oracle, IntelliJ / 리포트·보안·암호화·그리드·에디터 솔루션 연동
- 데이터 범위: 2010년 이후 쇼박스 전 작품 + 외부 계약

## 배경

기존 정산 사이트가 있었으나 업무가 비효율적이고 체계화되어 있지 않아, 기존 사이트를 토대로 정산 체계를 재설계해 신규 구축(리뉴얼).

## 담당 메뉴 (전반 참여)

영화 등록 · 지방 배급사 배분 · 기획개발 작품정보 · 투자채권 관리 · 배급대행 · 부분투자 계약 · 비용관리(예산/비용) · 매출관리 · 정산관리 · CMS(사용자·권한 관리 포함)

## 정산 구조 (도메인)

영화사·투자사·배급사 간 계약(지분율, 부가계약)을 기준으로 수익을 배분.

1. 극장 매출: 관객 수 × 객단가 → 부가세·영화발전기금 공제
2. 극장 부율 정산: 극장과 배급사가 부율(한국영화 통상 5:5 내외)로 분배
3. 배급수수료 공제
4. 투자사 제작비·마케팅비(P&A) 회수
5. 남은 수익을 계약 지분율에 따라 투자사·제작사 배분
6. 부가판권(IPTV·OTT 등), 지방 배급, 배급대행, 부분투자 계약은 계약 조건별로 별도 정산 후 합산

※ 일반적인 한국 영화 수익 배분 구조 기준. 실제 시스템의 세부 규칙은 본인 확인 필요.

## 문제 해결

### 1. 자주 바뀌는 공통 영역
- Problem: 여러 메뉴가 공유하는 공통 로직·코드가 자주 바뀌어 다른 팀 작업에 연쇄 영향
- Decision: 공통부 전담 팀을 따로 구성해 변경 창구를 일원화. 소스 구조를 먼저 파악한 뒤 메뉴 로직을 공통부와 최대한 독립적으로 분리
- Result: 공통 변경이 개별 메뉴 개발에 주는 영향을 줄이고 일정대로 진행

### 2. 원격지 근무로 인한 시차 협업
- Problem: 팀원 대부분이 원격지 근무라 일하는 시간대가 서로 달라 즉시 확인이 어려움
- Decision: Teams로 실시간 소통, 결정 사항·질의는 게시판에 남겨 비동기로 답을 받는 방식으로 정착
- Result: 협업 공백 없이 원활히 진행

### 3. 보안 VM(소스 반출 제한) 개발 환경
- Problem: 보안상 VM 안에서만 개발, 복사·붙여넣기와 외부 도구 사용 제한, 소스 반출 불가
- Decision: 기존 코드 구조를 분석해 요구사항에 맞게 단계적으로 변경. 복잡한 부분은 관리자 승인 절차를 거쳐 필요한 코드만 반출해 외부 도구로 검토
- Result: 보안 규정을 지키면서 일정 내 개발 진행
